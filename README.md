## 5) 트러블 슈팅
# 1. fatal: not a git repository 오류 해결
1. 문제 상황 (Issue)
로그 파일 3개를 생성한 후, GitHub 원격 저장소로 업로드하기 위해 git push 명령어를 실행했으나 아래와 같은 에러가 발생하며 푸시가 실패함.

fatal: not a git repository (or any of the parent directories): .git

2. 원인 분석 (Cause)
현재 명령어 실행 위치가 Git 저장소(Repository)로 지정되어 있지 않거나, .git 폴더가 생성되지 않은 일반 디렉토리에서 Git 명령어를 수행하여 발생한 문제임.

3. 해결 과정 (Solution)
디렉토리 위치 확인: pwd (또는 cd) 명령어로 현재 작업 위치가 맞는지 검토함.

저장소 초기화: git init 명령어를 실행하여 현재 폴더를 Git 저장소로 초기화함.

기본 브랜치 설정: 깃허브의 기본 브랜치 이름 규칙에 맞춰 git branch -M main으로 브랜치명을 main으로 변경함.

상태 검증: git status를 통해 트래킹 대상 파일 목록(로그 파일 3개)이 정상적으로 인식되는 것을 확인함.

4. 결과 및 배운 점 (Result & Lessons Learned)
결과: Git 저장소가 정상적으로 구성되어 파일들이 추적(Tracked) 상태로 전환되었으며, 깃허브로 성공적으로 업로드를 완료함.

배운 점: Git 관련 명령어를 실행하기 전에는 항상 현재 디렉토리가 .git이 존재하는 저장소 내부인지 확인하는 습관이 필요함을 배움.


# 2. cd: no such file or directory 오류 해결
1. 문제 상황 (Issue)

도커 운영 및 검증 로그 생성을 위해 터미널에서 프로젝트 폴더로 이동(cd)하려고 했으나, 아래 에러가 출력되며 디렉토리 이동에 실패함.

cd: no such file or directory

2. 원인 분석 (Cause)

지정한 경로에 대상 폴더가 존재하지 않거나, 현재 터미널의 작업 위치(경로)가 프로젝트 폴더가 있는 상위 위치와 달라서 발생한 경로 참조 오류임.

3. 해결 과정 (Solution)

현재 위치 확인: pwd 명령어를 입력하여 현재 터미널이 바라보고 있는 디렉토리 경로를 확인함.

사용자 계정 및 계정 경로 확인: whoami 명령어로 현재 사용자 이름을 확인하고 사용자 홈 디렉토리 위치를 재검토함.

폴더 및 파일 목록 조회: ls (또는 Windows의 경우 dir) 명령어를 통해 현재 위치에 실제 존재해 있는 파일과 폴더 목록을 조회하고 정확한 프로젝트 경로를 탐색함.

필요 폴더 생성: 올바른 위치로 이동한 뒤, 로그 저장을 위한 폴더가 필요함을 확인하고 상위 경로까지 한 번에 생성해 주는 mkdir -p logs 명령어를 실행하여 logs 폴더를 정상적으로 생성함.

4. 결과 및 배운 점 (Result & Lessons Learned)

결과: 경로 오류를 바로잡고 필요한 logs 폴더를 정상 생성하여, 도커 운영/검증 로그 작업에 필요한 디렉토리 구조를 성공적으로 갖춤.

배운 점: cd 명령이 실패했을 때는 당황하지 않고 pwd와 ls를 이용해 현재 내 위치와 주변 폴더 구조를 탐색하는 것이 우선이며, mkdir -p 옵션을 활용하면 경로 생성 작업을 효율적으로 처리할 수 있음을 배움.
